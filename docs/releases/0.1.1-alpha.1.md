# Spare 0.1.1 Alpha 1 — Desktop Preview

Spare now has a desktop application for giving a computer a useful local job
without beginning in the terminal. This is an early alpha intended for
engineering evaluation and hands-on testing, not production use.

## What's included

- Automatic first-run initialization and per-user background-service setup.
- A visual setup flow for the built-in Site, Drop, and Hook recipes.
- Native folder selection for serving a Site or receiving files with Drop.
- Start, stop, status, local-network address, and QR-code controls.
- Live activity, recipe health, native notifications, and recovery guidance.
- macOS menu-bar and Windows/Linux system-tray integration.
- Drag-and-drop support for folders, Drop uploads, `.sp` recipe packages, and
  `.spare-backup` files.
- Safe local inspection of built-in and packaged `.sp` recipes.
- Export and restore for recipe data that uses a selected folder.
- Desktop settings for login behavior, notifications, recipe storage, repair,
  browser-dashboard access, and uninstall.
- The advanced `spare` CLI and `spared` daemon bundled with the desktop
  application.

Spare includes three trusted recipes:

- **Site** serves a selected folder as a read-only local website.
- **Drop** lets nearby devices send files into a selected folder.
- **Hook** captures, inspects, and replays webhook requests for local testing.

## Platform status

- macOS Intel has been built and exercised natively.
- macOS Apple Silicon is cross-built and still requires its native acceptance
  pass.
- Windows 11 amd64 is cross-built and structurally checked, but its installer,
  tray, login restart, and WebView2 behavior still require native acceptance
  testing.
- Linux has a native GTK/AppIndicator build path; clean-machine Ubuntu,
  Debian, and Raspberry Pi acceptance testing remains outstanding.

Download the archive that matches both your operating system and CPU
architecture. On macOS, use `darwin_amd64` for Intel and `darwin_arm64` for
Apple Silicon.

## Important alpha limitations

- The applications are unsigned and are not notarized.
- Only one recipe can be active at a time.
- Site, Drop, and Hook are designed for trusted local networks. Their shared
  pages do not provide accounts or TLS.
- Drop does not provide malware scanning.
- Hook request history is held in memory and is cleared when Hook stops.
- Third-party recipe execution, remote internet access, containers,
  automatic updates, and telemetry are not included.
- Windows, Apple Silicon, and Linux still need the native acceptance passes
  described above.

Spare does not delete a selected Site folder, Drop destination, received file,
or restored folder when a recipe is removed or Spare is uninstalled.

## What to test

Please test:

- First launch and initialization.
- Site, Drop, and Hook setup.
- Access from another device on the same local network.
- Start, stop, menu-bar or tray, and login restart behavior.
- Paths containing spaces and Unicode characters.
- Drag-and-drop and `.sp` package viewing.
- Backup export and restore.
- Repair and uninstall without loss of selected-folder data.

When reporting a problem, include the operating system, CPU architecture,
Spare version, the command or action used, and the output of `spare doctor`.
